# Как я устал объяснять друзьям про белый IP и написал утилиту для проброса портов в один клик

Привет, Хабр!

Я ещё только начинаю свой путь в коммерческой разработке и программировании на Python. Но, как это часто бывает, лучший способ научиться писать реальный софт — это попытаться решить проблему, от которой у тебя и твоих знакомых уже давно дёргается глаз.

Моей головной болью стал вопрос: **«Почему мы опять не можем нормально поиграть в кооперативе на собственном сервере?»**

Знакомая картина: собираешься поиграть с друзьями в *Minecraft*, *Palworld*, *CS2* или *Valheim*. Поднимаешь сервер у себя на домашнем ПК. Скидываешь ребятам свой IP из 2ip.ru... и у всех бесконечный тайм-аут подключения.

Дальше начинается классический квест:
1. «А у тебя IP белый или серый?» — «Э-э-э, ну в 2ip цифры написаны...»
2. «Надо порты пробросить на роутере!» — «Я не знаю пароль от 192.168.1.1, его мастер из техподдержки настраивал 5 лет назад».
3. В отчаянии все ставят Hamachi или Radmin VPN, ловят дикие задержки, синие экраны или проблемы с виртуальными адаптерами.

Чтобы навсегда закрыть этот вопрос, я написал и выложил в open source утилиту **NetHub**. В этой статье хочу рассказать, как она устроена под капотом, как работает автопроброс портов без пароля от роутера и какие грабли я собрал по пути.

---

## В чём вообще техническая проблема?

### 1. Серый IP (CGNAT) vs Белый IP
Многие начинающие пользователи уверены: если какой-то сайт показывает их внешний IP, значит, они видны в интернете напрямую. Но из-за дефицита IPv4 подавляющее большинство провайдеров (Ростелеком, МТС, Дом.ру и т.д.) используют **CGNAT (Carrier-Grade NAT)** согласно RFC 6598 (диапазон `100.64.0.0/10`).

При Сером IP адрес на WAN-интерфейсе вашего роутера — это не глобальный адрес, а внутренняя подсеть провайдера. Один внешний публичный адрес делится между десятками квартир. Любой входящий пакет из глобального интернета на ваш порт просто отбрасывается маршрутизатором провайдера. 

Сколько бы портов вы ни пробрасывали на своём домашнем роутере — при Сером IP входящие соединения **невозможны в принципе**.

### 2. Админка роутера и лень
Даже если у пользователя честный белый IP, чтобы друзья зашли на сервер, нужно сделать Port Forwarding (пробросить внешний порт на локальный IP компьютера в подсети, например `192.168.1.150`).
Для многих вход в веб-интерфейс роутера — это непреодолимый барьер: забытые пароли, странные прошивки (у каждого вендора свой интерфейс — от Keenetic до TP-Link и Huawei), страх что-то сломать.

## Архитектура решения: NetHub

Я решил сделать инструмент, который запускается в один клик (без необходимости ставить Python, Node.js или базы данных) и объединяет два режима:
1. **Интерактивный консольный CLI** — для быстрой диагностики.
2. **Self-Hosted Web UI** — локальная веб-панель на `http://localhost:8080`, где всё делается большими понятными кнопками.

### Схема взаимодействия:

```text
  [ Пользователь ]
         │
    ┌────┴──────────────────────────┐
    ▼                               ▼
[ Консоль CLI ]            [ Веб-панель Web UI ]
    │                               │
    └──────────────┬────────────────┘
                   ▼
         [ NetHub Engine (Python) ]
         ├── Детектор Белый/Серый IP (STUN/Geo)
         ├── 1-Click UPnP Клиент (SSDP + SOAP)
         ├── WAN Reachability Checker (Внешний пинг)
         └── Диспетчер процессов (Запуск .bat серверов)
                   │
         ┌─────────┴─────────┐
         ▼                   ▼
[ Домашний Роутер ]     [ Глобальный Интернет ]
(Проброс без пароля)    (Проверка доступности)
```

## Как мы открываем порты без логина и пароля: UPnP SOAP

Почти во всех современных роутерах с завода включен протокол **UPnP (Universal Plug and Play)**. Именно его используют торрент-клиенты и игровые приставки (PlayStation/Xbox), чтобы автоматически резервировать за собой порты.

В коде NetHub это реализовано на чистом Python без тяжёлых сторонних библиотек:

1. **Обнаружение роутера через SSDP:**
   Отправляем широковещательный UDP-запрос `M-SEARCH` на адрес `239.255.255.250:1900`:
   ```http
   M-SEARCH * HTTP/1.1
   HOST: 239.255.255.250:1900
   MAN: "ssdp:discover"
   MX: 2
   ST: urn:schemas-upnp-org:device:InternetGatewayDevice:1
   ```
2. **Получение Control URL:**
   В ответе роутера считываем заголовок `Location`, скачиваем XML-дескриптор устройства и находим URL управления службой `WANIPConnection:1` (или `WANPPPConnection:1`).
3. **Отправка SOAP-запроса на проброс:**
   Формируем XML-пакет `AddPortMapping` с указанием нужного порта (например, TCP `25565` для Minecraft), локального IP нашего компьютера и времени аренды.

Роутер применяет правило мгновенно — **никакой авторизации в веб-морде 192.168.1.1 не требуется!**

## Проверка внешней доступности (WAN Reachability)

Мало пробросить порт — нужно убедиться, что из интернета он действительно доступен. NetHub отправляет запрос к независимой внешней ноде, которая пробует подключиться к вашему внешнему IP и целевому порту, возвращая точный результат: порт открыт и слушает, либо соединение сброшено фаерволом.

## Запуск игровых серверов прямо из браузера

В конфиге `config.json` можно прописать ярлыки запуска:
```json
{
  "shortcuts": [
    {
      "name": "Minecraft Vanilla 1.20",
      "path": "C:\\Servers\\Minecraft\\start.bat",
      "working_dir": "C:\\Servers\\Minecraft"
    }
  ]
}
```
После этого в веб-интерфейсе появляется карточка сервера с кнопкой запуска. Сервер стартует в отдельном процессе Windows, не блокируя веб-сервер.
